# All Features

TrueVision is a full-stack facial deepfake image detection project. It combines an Angular frontend, Flask API backend, PostgreSQL database, PyTorch/Swin-based inference, image validation, Grad-CAM visual evidence, saved user history, downloadable reports, and a model performance dashboard.

## 1. Project Purpose

TrueVision helps a user upload a face image and receive a guided decision about whether the image appears more likely real or fake. The project is designed for understandable review, not just a raw model output.

The app focuses on:

- Detecting possible facial deepfake manipulation.
- Showing a confidence score with the prediction.
- Giving a plain-language explanation of the result.
- Showing highlighted model focus areas through Grad-CAM output.
- Supporting guest usage for quick checks.
- Supporting account-based usage for saved history and downloadable reports.
- Presenting model performance in a way that non-technical users can understand.

## 5. Backend API Features

### Authentication API

- `GET /api/auth/me` checks current authenticated user.
- `POST /api/auth/register` creates a new user and logs them in.
- `POST /api/auth/login` authenticates an existing user.
- `POST /api/auth/logout` clears the active session.

### Upload API

- `POST /api/upload` accepts image uploads.
- Handles both guest and authenticated uploads.
- Validates file presence, file type, file size, and image content.
- Runs quality filtering before model prediction.
- Runs model inference and Grad-CAM generation.
- Saves authenticated user results to PostgreSQL.
- Stores guest result data in session for temporary preview.

### Results API

- `GET /api/results` returns saved results for the logged-in user.
- `GET /api/results/<id>` returns a specific saved result.
- `POST /api/results/<id>/feedback` saves feedback for a result.
- Feedback can mark whether the user agrees or disagrees with the model output.

### Media API

- `GET /api/media/result/<id>/image` serves a saved result's uploaded image.
- `GET /api/media/result/<id>/gradcam` serves a saved result's highlighted Grad-CAM image.
- `GET /api/media/guest/image` serves the latest guest-uploaded image from session.
- `GET /api/media/guest/gradcam` serves the latest guest Grad-CAM image from session.
- Media path validation prevents unsafe file access.

### Performance API

- `GET /api/performance` returns model performance rows and best model data.
- Used by the Angular Model Report page.
- Handles empty performance table state with a clear error response.

## 6. Database Features

The project uses PostgreSQL for persistent data.

### User Table

### Result Table

- F1 score,

- false negative rate,
- true negative rate,

- PR-AUC,
- confusion matrix data.

## 7. Performance Data Seeding

- Includes `backend/scripts/seed_performance_from_pdf.py`.
- Seeds the `performance` table using project performance values derived from `TrueVision.pdf`.
- Creates or updates performance rows for multiple tested models.
- Current performance dataset includes 12 model rows.
- Best visible model from the seeded table is Stage-2 Swin.
- Performance counts such as TP, TN, FP, and FN are derived approximations based on the documented test size and class split.

## 14. Main End-to-End Flow

1. User opens TrueVision.
2. User uploads a PNG/JPG/JPEG face image.
3. Frontend checks file type, size, and basic dimensions.
4. Backend validates the uploaded image.
5. Backend runs image filtering to reject unsuitable images.
6. Backend runs model inference.
7. Backend generates Grad-CAM visual evidence.
8. Guest users receive a temporary result preview.
9. Logged-in users receive a saved result.
10. User reviews prediction, confidence, explanation, highlighted areas, and recommendation.
11. Logged-in user can submit feedback or download a report.
12. Logged-in user can later return to My Results and reopen saved checks.
